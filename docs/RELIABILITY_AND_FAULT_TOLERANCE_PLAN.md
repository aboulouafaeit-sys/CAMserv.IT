## 1. Resilience Philosophy & Architectural Guarantees

In an enterprise video surveillance and security intelligence system, software failure must never lead to catastrophic loss of coverage, unmonitored blind spots, or corrupted digital evidence.

CAMserv enforces four resilience axioms:
1. **Compartmentalization:** A failure in an analytical, decoding, or alerting module must NEVER crash the core server or drop unaffected video streams.
2. **Predictable Degradation:** Under resource exhaustion (RAM, GPU, CPU, Disk), the system sheds compute load deterministically (dropping inference frame rate before dropping acquisition frames; purging low-tier routine video before touching pre-roll incident evidence).
3. **Fail-Closed Security & Privacy:** A crash or fault in the anonymization or redaction pipeline halts public streaming rather than leaking unredacted identities.
4. **Deterministic State Recovery:** Every stateful component (vault, database, tracker, audit log) must recover to a verified consistent state upon process restart without human intervention.

## 2. Exhaustive 16-Scenario Failure Containment Matrix

| # | Failure Scenario | Detection Mechanism | Containment Strategy | Autonomous Recovery Procedure | Data Preservation | Operator Notification | Audit Logging | Acceptance Test |
|---|------------------|---------------------|----------------------|-------------------------------|-------------------|-----------------------|---------------|-----------------|
| 1 | **One camera disconnects** | Ingest watchdog detects zero incoming frames for $> 3.0\text{s}$ or EOF on socket. | Isolate camera ingestion thread/process; mark camera status as `DISCONNECTED`; pipeline continues processing remaining streams. | Exponential backoff reconnect loop ($1\text{s}, 2\text{s}, 4\text{s}, \dots, \max 60\text{s}$) with TCP SYN timeout. | Mark stream gap in time-series index; preserve existing pre-roll buffer in RAM. | Yellow warning badge on camera HUD card in Web Console. | `STREAM_DISCONNECT` entry in SHA-256 chained audit log. | `test_scenarios.py::test_camera_disconnect_isolation` |
| 2 | **All cameras disconnect** | Network interface monitor detects link drop or aggregate ingest FPS $= 0$ across all streams. | Put inference engine into low-power idling state; maintain API server and web console responsiveness. | Continuous network probe; autonomous batch reconnect when link state returns to UP. | Retain last known state and evidence vaults intact; no disk thrashing. | Red persistent critical banner on Web Console; sound audible tone. | `AGGREGATE_NETWORK_OUTAGE` logged with timestamp. | `test_scenarios.py::test_all_cameras_offline_graceful_idle` |
| 3 | **RTSP authentication fails** | Decoder/client receives HTTP/RTSP 401 Unauthorized or 403 Forbidden. | Terminate reconnect loop immediately to prevent IP lockout or camera brute-force rate-limiting. | Enter `AUTH_FAILED` quarantine; require manual credential update or key rotation via API. | Retain historical recordings; halt active ingestion. | Modal alert on Web Console prompting administrator credential review. | `CAMERA_AUTH_FAILURE` logged with camera ID and remote IP. | `test_scenarios.py::test_rtsp_auth_failure_backoff` |
| 4 | **Camera sends corrupted packets** | OpenCV/FFmpeg packet parser detects malformed H.264 NAL units, frame size $= 0$, or decoding artifact. | Catch `DecodingError` in decoder worker; discard corrupted slice; increment stream corruption counter. | Reset video decoder context on next valid IDR keyframe; continue stream seamlessly. | Corrupted slice is dropped; valid prior and successor frames preserved. | Minor status indicator on stream health panel if corruption $> 5\%$. | `PACKET_CORRUPTION_EVENT` logged if threshold exceeded. | `test_adversarial.py::test_corrupted_frame_handling` |
| 5 | **A video decoder crashes** | Subprocess watchdog receives non-zero exit code or SIGSEGV from decoder worker. | Subprocess isolation prevents crash from affecting parent process or sibling decoders. | Watchdog immediately spawns clean worker instance; restarts stream from latest keyframe. | Zero loss to existing vault archives; transient $\sim 500\text{ms}$ video gap recorded in audit log. | Toast notification to operator: "Stream decoder restarted". | `WORKER_CRASH_RESTART` logged with core dump trace. | `test_resilience.py::test_decoder_subprocess_crash_recovery` |
| 6 | **AI model fails to load** | Model loader catches `FileNotFoundError`, corrupted ONNX checksum, or TensorRT engine failure. | Fall back immediately to deterministic CPU heuristic or synthetic fallback detector; mark `is_fallback: True`. | Schedule background model verification; retry loading secondary model checkpoint. | Video recording continues uninterrupted; metadata flags predictions as heuristic. | Amber banner: "AI Acceleration Degraded - Running Heuristic Fallback". | `MODEL_LOAD_FAILURE` with checkpoint SHA-256 logged. | `test_detector.py::test_model_fallback_mode` |
| 7 | **GPU memory (VRAM) exhausted** | PyTorch/CUDA runtime catches `torch.cuda.OutOfMemoryError` or NVML VRAM utilization $> 95\%$. | Empty CUDA cache (`torch.cuda.empty_cache()`); dynamically reduce batch size from 4 to 1; switch to half-precision FP16. | If OOM persists, dynamically migrate inference worker to CPU (`TIER_1_EDGE`) without restarting server. | All video recording and vault operations remain active. | Warning icon on System Health widget: "GPU VRAM Pressure Shedding". | `GPU_VRAM_OOM_RECOVERY` logged with allocated byte metrics. | `test_hardware.py::test_vram_exhaustion_shedding` |
| 8 | **CUDA becomes unavailable** | CUDA driver crashes or device disappears from PCI bus. | Catch `CUDA_ERROR_UNKNOWN`; release GPU device context; transfer all neural workers to CPU OpenVINO/ONNX. | Run inference pipeline on host CPU multi-threading; drop inference frame rate to match budget ($5\text{ FPS}$). | Video acquisition and tamper-evident storage remain 100% operational. | Critical alert: "Hardware Acceleration Lost - CPU Operational". | `ACCELERATOR_OFFLINE` logged with driver diagnostic. | `test_hardware.py::test_cuda_failover_to_cpu` |
| 9 | **RAM usage increases continuously** | Platform adaptive manager detects process RSS RAM $> 85\%$ of host capacity. | Force garbage collection; flush non-critical telemetry caches; reduce RAM pre-roll buffer from 15s to 5s. | If leak persists, trigger graceful restart of affected worker subprocess; API core remains online. | Write pending RAM buffer chunks to disk before worker recycling. | Notification on Admin Diagnostics screen. | `MEMORY_PRESSURE_RELIEF` logged with memory delta. | `test_adaptive.py::test_memory_watchdog_threshold` |
| 10 | **Database becomes unavailable** | SQLite locks up or filesystem I/O fails with `OperationalError: database is locked`. | Divert incoming events and audit logs to in-memory FIFO spillover queue ($10,000$ entries); avoid dropping events. | Exponential retry with WAL checkpoint recovery; recreate WAL file if corrupted. | Zero data loss; queue drains atomically into database upon lock resolution. | Amber status indicator on database health icon. | `DATABASE_LOCK_RECOVERY` logged once reconnected. | `test_sqlite_store.py::test_database_retry_and_spillover` |
| 11 | **Storage becomes full** | Vault storage monitor detects free disk space $< 10\%$. | Activate Tiered Storage Purge: delete oldest Tier 1 (routine 1080p continuous video) while strictly preserving Tier 3 sealed evidence. | Enforce WORM retention rules; refuse non-incident recordings until disk space is cleared. | Sealed forensic evidence packages are never deleted. | Red flashing disk capacity warning; automated webhook to SysAdmin. | `STORAGE_EXHAUSTION_PURGE` logged with deleted byte counts. | `test_adaptive_vault.py::test_storage_full_tiered_purge` |
| 12 | **Power interrupted during writing** | Sudden power cutoff or kernel panic while evidence archive is being written to disk. | Atomic file operations: write to `.tmp` file, flush OS disk buffers via `fsync()`, atomic rename to `.vault`. | On startup, vault scrubber scans directory; removes incomplete `.tmp` files; verifies Merkle roots of all archives. | All previously finalized `.vault` packages remain cryptographically valid. | Startup self-test report displayed on admin console. | `DIRTY_SHUTDOWN_RECOVERY` logged on next boot. | `test_forensics.py::test_atomic_write_power_loss` |
| 13 | **An update fails halfway through** | Package or model update process fails checksum validation or encounters missing dependency. | Staged blue/green deployment directory; update writes to isolated staging directory. | Immediate rollback to active production directory; abort execution of new binaries. | Existing configuration, database, and evidence untouched. | System notification: "Update aborted - Rolled back safely". | `UPDATE_ROLLBACK_EVENT` logged with failure reason. | `test_deployment.py::test_atomic_update_rollback` |
| 14 | **Background worker unresponsive** | Heartbeat monitor receives no ping from ingestion or inference worker for $> 10.0\text{s}$. | Mark worker as stalled; terminate unresponsive process via `SIGKILL` after grace period. | Fork new worker process; re-initialize pipeline queues and shared memory handles. | Drop-oldest queue discards unhandled analytical frames; video stream resumes immediately. | Operator toast: "Background worker recovered". | `WORKER_HEARTBEAT_TIMEOUT` logged with thread dump. | `test_pipeline.py::test_worker_heartbeat_supervisor` |
| 15 | **Application terminated unexpectedly** | Process receives unhandled signal or OS kill (`SIGTERM` / `SIGINT`). | Graceful shutdown handler: stops capture loops, drains in-flight queue, flushes audit log to disk, closes DB connection. | Systemd / Docker supervisor restarts CAMserv service with clean environment. | Database in WAL mode recovers cleanly without corruption; audit hash chain remains contiguous. | Email / Webhook alert to security team upon restart. | `SYSTEM_SHUTDOWN` and subsequent `SYSTEM_STARTUP` logged. | `test_main.py::test_graceful_shutdown_drain` |
| 16 | **Network disconnected for long period** | Network outage lasts hours or days. | Platform enters Autonomous Sovereign Mode: local storage records incidents, local threat engine evaluates alerts, local alarms sound. | Automatic sync and alert re-transmission when network connectivity is restored. | Full local digital evidence retained up to local disk capacity. | Offline banner on local physical console monitor. | `NETWORK_RESTORED` logged with downtime duration. | `test_scenarios.py::test_extended_offline_sovereignty` |
